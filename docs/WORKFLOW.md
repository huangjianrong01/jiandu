# 笺读 · 笺校 工作流

> 产品使用说明（亦可作为 App 内「关于」面板的文案源）。
> 定位：让用户——尤其是第一次打开「笺校」的人——三分钟内明白这两条主线怎么走。
> 风格基调：宣纸底色、毛玻璃、极简单字，与产品本体一致。

---

## 一、两条主线

笺读（读古籍）与笺校（校古籍）是同一本书的两种姿态：

- **笺读** = 把书「读顺」：排版、句读、注音、夹注、眉批，最后听书或导出。
- **笺校** = 把书「校对」：左图（原书扫描）对右文（转录文本），点哪指哪，逐字核红。

二者共享同一套「宣纸 + 朱砂」视觉语言，区别只在**右侧那一半在做什么**。

---

## 二、笺读工作流

1. **入库**：书架按「经 / 史 / 子 / 集 / 丛」分类；本地书一键加入。
2. **排版**：自动套用天头∶地脚 3∶2、双叶等宽、中缝居中、句读为字内深层子——古籍的「骨相」由排版引擎兜底，不用手调。
3. **句读与注音**：古籍缺标点？引擎补句读（斜墨滴读类 / 〇句类）；生僻字可挂横排注音（朱砂色，贴字右侧）。
4. **批注**：天头写眉批、行间写双行夹注、书口留书名——批注是「叠」在纸上的，不破坏版心。
5. **听书**：底部听书条极简横排（倍速用数字 0.8 / 1.0 / 1.25），不占版面。
6. **导出**：PNG / 分享图 / Markdown / 朱批录 / Anki CSV×2 / Obsidian 一卡一档——产出链是真正能收费的能力。

> 笺读的卖点是「句读与版式独一份」，读起来像捧着一册线装书，而不是盯着 PDF。

---

## 三、笺校工作流

1. **进工作台**：书架右下角「笺校」入口（阅读屏不加，保持阅读纯净）。
2. **左图**：导入原书扫描（PDF / 图片）。扫描版 PDF 是正常态——底图照渲、照翻、照导，点段落也给话；需要 OCR 时走「扫描识别」补全文。
3. **右文**：导入转录文本（Markdown / 纯文本）或直接手敲。右侧是纯文本流式稿纸，宋体 #333、1.7 倍行距。
4. **点哪指哪**：点右侧任意一行 → 光标落下 + 左侧原图对应区域高亮框亮起。空白区点击也落光标（坐标换算夹到末行），绝不「点了没反应」。
5. **繁简**：右上角「字」面板切 原文 / 简 / 繁（非破坏显示）；选中一段右键可就地转简/转繁。
6. **双文比对**（规划中）：导入两个版本（如《道德经》甲乙本），左文右文并排、滚动同步，新增绿、删除红删除线。
7. **导出**：六种产出（见上），把校勘成果带走。

> 笺校的卖点是「左图右文联动 + 句读排版」，这是竞品没有的校勘体验。

---

## 四、一套视觉语言贯穿始终

- **宣纸底色**：稿纸最亮一张纸（`PAPER_R`），左图纸略沉（`PAPER_L`），顶栏只深半个色阶（`CHROME`）。
- **毛玻璃**：分栏靠柔影 + 一根 5% 墨发丝线分出，绝不用黑边框。
- **极简单字**：按钮是一个字或短词（打开 / 导入 / 笺 / 字），不写长句子；朱砂只留给批注与激活态。
- **零噪音**：能收起来的（繁简、样式、队列）一律收成小卡，不占常驻工具栏。

这套语言是产品的签名，任何新功能（OCR / 繁简 / Diff）都不得破坏它。

## P0 · TEI 一键 UI（最简方案 · 立刻做）

**为什么最简**：TEI 导出内核 `jiandu_core::exporter::export_tei(&IrBook)` 已验证。目前只在主阅读器「更多 → 导出」里接了；对照模式内还没有按钮。

**方案**：在对照模式顶部操作栏加一枚「导出 TEI」按钮（与现有「保存对照图」红按钮同级），把当前右栏 `compare_text`（或已开书本 IR）喂给 `export_tei` 落盘 `.xml`。
- 复用 `save_compare_image` 同一套 rfd 保存框 + 沙盒记忆逻辑，不新造轮子。
- 绝不污染普通阅读界面（铁律）。
- 预计改动：< 30 行，集中在 `app.rs` 对照栏 + 一个 `export_compare_tei` 方法。

**验收**：对照模式下点按钮 → 弹保存框 → 生成标准 TEI P5，三路分离 + 实体标签。

## P1 · OCR 接入（macOS Vision FFI · 横排 / 竖排）

**为什么选 Vision**：macOS 自带 `Vision` 框架（`VNRecognizeTextRequest`），系统级、离线、免费、CJK 识别质量高，且原生支持**竖排文本识别**（`recognitionLanguages` + `VNRecognizeTextRequest` 的 `usesLanguageCorrection`）。不需要外部 API、不泄露书稿、零服务器成本。

**最简技术方案（纯 Rust 调 Vision，不引第三方 OCR 库）**：

1. **FFI 封装**：在已有 `crates/app`（macOS 壳）里加一个 `ocr_vision` 模块，用 `#[link(name="Vision")]` + `#[link(name="CoreML")]` 直接调 Objective-C Vision API（参考现有 `pdf_text.rs` 调 PDFKit 的 FFI 写法——同一套 `objc` 桥接模式）。
2. **请求配置**：
   - 横排：`recognitionLanguages = ["zh-Hans"]`，`usesLanguageCorrection = true`。
   - 竖排：Vision 对竖排 CJK 原生支持，设置 `recognitionLevel = .accurate` 即可。
3. **坐标输出**：每张识别出的 `VNRecognizedText` 取 `boundingBox`（归一化）→ 乘原图像素得 `x/y/w/h`，再按对照模式 JSON 格式（`glyphs: [{x,y,w,h,target}]`）+ 拼接 `text`，**直接喂给现有 `load_compare_json` 管线**。
   - 也就是说：OCR 的输出格式 = 对照模式已经能吃掉的 JSON。**零新数据模型**。
4. **落库**：识别结果写入 `crates/ocr-cli` 已有的 TEI 友好 JSON 出口（该 crate 是 V2.0 新增的独立 bin，不破 core 纯洁线）。

**验收**：「导入原图」后点「OCR 识别」→ 右栏自动填上识别文字 + 命中框 → 点左图字右文亮框、滚动同步全通。横排绝版书真机闭环完成。

**风险**：Vision 竖排识别偶有漏行，属模型误差，不致命——用户可手动补 `text`。

## P2 · 本地大模型接入（Ollama / llama.cpp · 校勘 / 句读 / 实体抽取）

**定位**：在 OCR + IR 之上做「智能层」，全部**本地离线**跑，书稿不出本机（商业化合规底线）。

**最简技术方案**：

1. **接入方式**：优先 **Ollama**（本地 HTTP，`http://localhost:11434`），模型用 `qwen2.5` 系列或专用古文小模型；备选 `llama.cpp` 直接嵌。复用 `crates/core/src/ai.rs` 已有的 `spawn_chat` 异步通道（V2.0 AI 句读已铺好）。
2. **三个子功能（按价值排）**：
   - **a. 实体抽取**：把 IR 正文丢给模型，抽人名 / 地名 / 书名 → 回填 TEI 的 `<persName>/<placeName>/<title>`。已有 `ai.rs` 提示词框架，增量只是「抽实体」prompt + 结构化解析。
   - **b. 校勘比对**：OCR 文字 vs 校本文字，模型标异文 → 直接进对照模式右栏高亮差异（复用命中联动红框）。这是「双屏对照」最自然的增值。
   - **c. AI 句读**：V2.0 已做主阅读器 AI 句读，对照模式可复用同一管线给 OCR 出来的无标点文本补句读。
3. **UI 入口**：对照模式顶部栏加「AI 校勘」「提取实体」两枚按钮（与导出 / 保存同级），结果落进现有 IR / TEI 模型，**不碰主引擎**。

**验收**：OCR 文字进模型 → 出实体标签 + 异文标注 → 一键导出带标注的 TEI。

**风险**：本地模型速度取决于机器；首批只做「异步 + 进度条」，不阻塞阅读。模型权重不打包进 App（用户自选装 Ollama）。

## 推进顺序建议

1. **P0（今天就能合）** → TEI 一键 UI，让对照模式产出闭环。
2. **P3（半天）** → 右栏编辑器，去掉 JSON 门槛。
3. **P1（1–2 天）** → Vision OCR，横排绝版书真机闭环（用户明天数据正好验证）。
4. **P4（1 天）** → 对齐落库，让对照结果可保存复用。
5. **P2（2–3 天）** → 本地大模型，校勘 + 实体，商业化钥匙。
6. **P5（最后，谨慎）** → 反向联动左图自动滚露字（易死锁，留到最后，且独立模块，崩了不影响主程序）。

> 全程铁律：新功能只长在对照模式 / 独立 crate（`ocr-cli` / `exporter` / `ai`），**绝不碰 `reader.rs` 主引擎**；每次增量后跑 `cargo test --workspace --release` + `bash scripts/check_core_purity.sh`，保证 V1.0 零回归。

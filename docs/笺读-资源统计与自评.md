### 1.3 怎么读这几个数

* **15.4 亿 token 里，97% 是「上下文重读」**。每一轮模型都要把此前所有消息
  （含我读过的源码、跑过的 cargo 输出）重新读一遍，这部分走的是缓存，单价很低，
  但账面上巨大。真正「写进去」的新信息只有 **3,728 万 token**。
* **输出只有 836 万 token**，占总量 0.5%。也就是说这个项目的成本几乎全在
  「反复读同一份越来越长的代码库」，不在「写」。
* 直观换算：3,728 万新增输入 ≈ 3,700 万汉字 ≈ **《史记》约 70 遍**（《史记》约 52 万字）。
  但输出 836 万 token ≈ 800 万字，比《四库全书总目》还长——其中近一半是我的
  「思考」过程，真正落到磁盘上的代码只有 2.8 万行。
* 模型分布：`hy3` / `step-5-preview` / `hy4-preview` / `hy3-x` / `deepseek-v4.1-flash`
  等多个模型接力（平台自动调度），故不做单一模型定价折算——口径不同，硬折会失真。

## 三、自我评价

### 3.1 做得好的

1. **纯计算模块 + 零依赖单测**。排版（`grid` / `gloss` / `punct` / `banxin` /
   `numcn` / `pipeline`）全部写成不碰 GPUI 的纯函数，坐标可以直接断言。
   399 个测试里绝大多数是这类——这也是本项目敢一路 +0.05 快速发版的原因：
   改坏了立刻红。
2. **抓住「刻本语汇」而不是套 UI 组件**。朱砂印章、题签、书脊线、极细墨线、
   鱼尾改成直线五边形、朱批用空心圈 + 细朱线……这些是反复推翻重做才有的，
   也是这个 App 和「一个竖排阅读器」的区别。
3. **Bug 修到根上**。数字被拆成「2/2/3」不是渲染时调坐标，而是源头把数字
   转汉字 + 渲染侧半格账兜底；古今割裂不是换个字体，而是整栏换语汇。
   这次的导入管线也是同一思路：不再「一个格式一套临时代码」。

### 3.2 做得糟的 / 我该更早说清楚的

1. **上下文重读占比过高（97%）**——这是我这边最大的浪费。会话拖到上亿 token
   之后，我每次回答都在重读一大堆历史源码。更省的做法应当是：**每个版本开新
   会话**，把「当前架构约定 + 待办」写进 `MEMORY.md` 作为唯一入口。我中途才
   这么做，前面十几亿 token 有一半是重复劳动。
2. **早期版本发得太密、命名太随意**（0.95 / 1.05 / 1.10 混着 semver 与显示名，
   还踩过 `1.05.0` 不是合法 semver 的坑）。版本号这件事本该一开始就定成
   「Cargo 写 X.Y.0、界面显示 X.Y」一条规则。
3. **GPUI 0.2.2 的能力盲区我探得晚了**。没有元素级旋转、没有 `backdrop-filter`、
   没有 dashed 边框，这三条我都是在做到一半才发现，导致「西文横躺 90°」
   最后退化成「同槽位直立」，分享面板的磨砂只能用半透明近黑模拟。**如果重来，
   我会在动手前先花半小时把渲染 API 的能力边界列成一张表**，而不是边做边撞。
4. **视觉验证一直是短板**。我读不到自己渲染出来的像素，只能靠你截图反馈再改。
   好几次「看起来不对」的问题（句读居中、鱼尾像黑桃）都是你指出来我才知道。
   这一点我至今没有真正解决——现在仍然是你看图、我改数。
5. **磁盘与构建**：release 构建要几 GB，我几次把机器压到告警线才想起来清
   `target/`。这类工程卫生本该内建到打包脚本里。

### 3.3 如果重来一遍

* 第 0 天：先写 `MEMORY.md` 的架构约定（已完成，但晚了两周）；先探 GPUI API 边界。
* 每个版本一个短会话，长会话只用来做「读代码定位」这类一次性任务。
* 视觉规格（字号、偏移、颜色）写进常量表而不是散在代码里——`punct.rs`、
  `banxin.rs` 后来是这么做的，早期 `reader.rs` 里还有不少魔法数字。
* 导入管线应该更早做。现在它让 md / txt / html / xml / epub 共用一条清洗链，
  如果 v0.5 就有它，中间能省掉至少五次「这个格式又漏了」的返工。

## 四、下一步建议（供你取舍）

1. **真机验证管线**：拿几本真实 epub / 网上下来的 GBK txt / 带脚注的 md 各导一遍，
   看章切得对不对、夹注有没有排成双行小字。这是新管线唯一没被真实数据验过的部分。
2. **官网素材**：你提过「到 1.0 上官网」。现在 1.20 了，`docs/` 下已有书架、
   分享、侧栏、导入四份可直接截图/录屏的 HTML 稿，可以当作官网的交互 demo。
3. **继续降本**：按 3.2 第 1 条，后续大改开新会话 + 只带 `MEMORY.md`，
   能把上下文重读砍掉一个数量级。

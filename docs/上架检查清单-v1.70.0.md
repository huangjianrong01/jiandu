### 本轮修掉的三个真 bug

1. **数据目录分裂（会让老书集体变空白）**
   书架索引在 `~/Library/Application Support/com.jiandu.app`，章节库却硬拼 `~/.jiandu`。
   Mac App Store 强制沙盒后 `HOME` 被重定向到容器 → 两条路径必然分裂。
   本机实测：旧库 7 部 3385 章，新库 1 部 799 章。
2. **书架凭空少书**
   新索引 1 本（楚辞注），旧索引 8 本（资治通鉴 / 船山遗书 / 古文辞类纂 / 四库全书 /
   〔春秋〕左丘明 / 宋词三百首 / 历代名家词集精华录 / 中国古代名著全本译注）。
3. **取当前日期还要 fork 一个 `date` 子进程**（沙盒下外部进程随时可能被拦）。

### 本轮性能实测（《资治通鉴》799 章 / 12002 叶 / 308 万字）

| 指标 | 改前 | 改后 |
|---|---|---|
| 首帧建索引 | 345ms | **127ms** |
| 冷跳到末叶 | 244ms | **116ms**（且开卷后由渐进预热铺满，实际不再触发） |
| 连续翻页 | 130µs / 叶 | 130µs / 叶（本来就黄油，未变） |

三处根因：① `hydrate_chapter` 每章开一次数据库（open + 3 条 PRAGMA + ATTACH）；
② `scan_to` 前缀和 `for k in 0..end` 每推进一章把全表重加一遍（O(n²)，799 章白算 32 万次）；
③ 跳远时同步干完全部扫描。修法：线程本地读连接缓存 + 前缀和续加 + **空闲帧渐进铺索引**
（每帧 8 章 ≈ 1.1ms，60 FPS 无感，一两秒铺满，之后跳任何一章都是 O(log n) 查表）。

## 五、打包命令

### 通用包（arm64 + Intel x86_64，推荐，v1.71.0 起默认产出）

```bash
rustup target add x86_64-apple-darwin      # 只需做一次
ARCH=universal ./scripts/make-mac-app.sh   # → dist/笺读.app（105M）
cd dist && zip -rX -y ~/Desktop/笺读-1.71.0-universal.zip 笺读.app
```

> `lipo -archs dist/笺读.app/Contents/MacOS/jiandu` → **x86_64 arm64**，
> 一份包 Apple Silicon 与 Intel 都能装。本机架构那份复用 `target/release`
> （不重复全量编译），只有另一份进独立 target 子目录。

### 本机架构（只 Apple Silicon）

```bash
./scripts/make-mac-app.sh            # → dist/笺读.app
cd dist && zip -rX -y ~/Desktop/笺读-1.71.0.zip 笺读.app
```

> ⚠️ 必须用 `zip -rX -y`（`._` 边车文件会破坏签名），不要用 `ditto`。

### App Store 提审（你拿到证书后再跑）

```bash
APPSTORE=1 \
APP_CERT="3rd Party Mac Developer Application: Your Name (TEAMID)" \
INSTALLER_CERT="3rd Party Mac Developer Installer: Your Name (TEAMID)" \
PROVISIONING_PROFILE=scripts/embedded.provisionprofile \
./scripts/make-mac-app.sh
```

产出 `dist/笺读-1.70.0-118.pkg`，用 **Transporter**（或 Xcode Organizer）上传到 App Store Connect。

> MAS 提审**不需要自己公证**（Apple 统一处理）。
> 但如果你同时做官网 DMG 直发，那条路必须 `xcrun notarytool` 公证。

## 七、v1.71.0（build 119）：第 15 / 16 / 18 条已解决

### 15 + 16 · 剪贴板原生化（osascript / pbpaste / pbcopy 全部下岗）

新增 `src/clipboard.rs` 作为**剪贴板唯一入口**，统一走 GPUI 平台层的
`App::write_to_clipboard / read_from_clipboard`——macOS 实现就是
`NSPasteboard.generalPasteboard()`：**零子进程、零新依赖、零权限弹窗**，
不需要 `com.apple.security.automation.apple-events`。

| 原实现 | 位置 | 新实现 |
|---|---|---|
| `osascript` 写 `«class PNGf»`（还要先落临时 PNG） | `reader.rs::copy_share_png` | `clipboard::write_png` 直写 `public.png` UTI，**不落盘** |
| `pbcopy` 灌 stdin | `reader.rs::copy_page_text` | `clipboard::write_text(cx, …)` |
| `pbpaste` 子进程 | `app.rs::note_paste` | `clipboard::paste_text(cx)`（换行压成空格，口径不变） |
| `pbpaste` 子进程 | `shelf.rs` 重命名框 / 书架搜索框 ⌘V | 同上 |

`note_paste` 签名改为 `note_paste(&mut self, text: &str)`——剪贴板由调用方
读，草稿模型保持纯粹。新增 2 条单测（换行压平 / 一字不落），全量
**548 passed / 0 failed**。

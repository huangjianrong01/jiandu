### 本轮修掉的三个真 bug

1. **数据目录分裂（会让老书集体变空白）**
   书架索引在 `~/Library/Application Support/com.jiandu.app`，章节库却硬拼 `~/.jiandu`。
   Mac App Store 强制沙盒后 `HOME` 被重定向到容器 → 两条路径必然分裂。
   本机实测：旧库 7 部 3385 章，新库 1 部 799 章。
2. **书架凭空少书**
   新索引 1 本（楚辞注），旧索引 8 本（资治通鉴 / 船山遗书 / 古文辞类纂 / 四库全书 /
   〔春秋〕左丘明 / 宋词三百首 / 历代名家词集精华录 / 中国古代名著全本译注）。
3. **取当前日期还要 fork 一个 `date` 子进程**（沙盒下外部进程随时可能被拦）。

### 本轮性能实测（《资治通鉴》799 章 / 12002 叶 / 308 万字）

| 指标 | 改前 | 改后 |
|---|---|---|
| 首帧建索引 | 345ms | **127ms** |
| 冷跳到末叶 | 244ms | **116ms**（且开卷后由渐进预热铺满，实际不再触发） |
| 连续翻页 | 130µs / 叶 | 130µs / 叶（本来就黄油，未变） |

三处根因：① `hydrate_chapter` 每章开一次数据库（open + 3 条 PRAGMA + ATTACH）；
② `scan_to` 前缀和 `for k in 0..end` 每推进一章把全表重加一遍（O(n²)，799 章白算 32 万次）；
③ 跳远时同步干完全部扫描。修法：线程本地读连接缓存 + 前缀和续加 + **空闲帧渐进铺索引**
（每帧 8 章 ≈ 1.1ms，60 FPS 无感，一两秒铺满，之后跳任何一章都是 O(log n) 查表）。




产出 `dist/笺读-1.70.0-118.pkg`，用 **Transporter**（或 Xcode Organizer）上传到 App Store Connect。

### 15 + 16 · 剪贴板原生化（osascript / pbpaste / pbcopy 全部下岗）

| `pbpaste` 子进程 | `shelf.rs` 重命名框 / 书架搜索框 ⌘V | 同上 |

`note_paste` 签名改为 `note_paste(&mut self, text: &str)`——剪贴板由调用方
读，草稿模型保持纯粹。新增 2 条单测（换行压平 / 一字不落），全量
**548 passed / 0 failed**。

### 「导出当前页图片」新链路（用户点名要打通的三段）

1. **底层 `render_leaf_png`（reader.rs）** —— 离屏重绘，不读屏幕：
   * 正文取自**当前叶的排版结果**（`page_at` → 只要 `GlyphKind::Char`，
     繁简形态与屏幕一致，朱批逐字带过来）；
   * 走 `share_layout::layout` → `share_paint::render_png`（CoreGraphics
     位图 + CoreText 逐字落笔），与分享卡同一套已验证的光栅器；
   * 画面只留 **宣纸 + 天头地脚 + 版框界行 + 正文 + 朱印**：落款 / 日期 /
     批注列 `show_*` 全 false——**顶栏、页码、浮层都进不了图**；
   * 纸色 / 栏色**跟阅读界面当前主题走**（纸色亮度分宣纸 / 暗金，丝栏偏朱
     取朱丝栏、否则乌丝栏），不是分享抽屉那套偏好；
   * 分辨率**与窗口无关**：长边恒 **2160（2× 高清）**，短边按纸面真实比例
     （`leaf_png_size`），探针取不到尺寸时回退 1080×1920 基准。
   ⚠️ **只读排版结果，一行没碰排版引擎**（分页 / 网格 / 锚点全未改）。
2. **原生保存框（rfd）** —— 默认名 **`笺读_<书名>_第N叶.png`**（可改）；
   对话框标题「印制本叶（高清 PNG）」；**取消 = 正常结果**（提示「已取消保存」，
   不 panic、不报错红）；落盘不再「先写临时文件再拷一份」，直接写字节。
3. **UI 菜单绑定** —— 顶栏「导出」→「导出当前页图片」→ `export_page_png`
   （保持 `on_mouse_down`：阅读根 div 上挂着「点纸面收菜单」的 mousedown，
   改 `on_click` 会让菜单在抬起前被卸载、click 永不触发，详见代码注释）。
   成功后弹极简 Toast：**「本叶已印制」**（副行只带文件名，完整路径进 `notice`）。

**Toast 的三种收起方式**：点右侧「关」/ 按 **Esc** / 点纸面任一处。
单字按钮用 CJK「关」（U+2715 那类拉丁区符号在 GPUI 里是零宽，画不出来）。
帮助面板「导出」组新增四行说明（清晰度口径 / 文件名 / 提示如何收起），
「Esc」行的说明也补上了「收起导出提示条」。

### 17 · `afplay` → 原生 `NSSound`

`sound::page_turn` 不再 fork 子进程：FFI 直调 `objc_getClass` /
`sel_registerName` / `objc_msgSend`（都在 libobjc 里，**不加新依赖**），

`play` 本身异步、主线程直调不阻塞。非 macOS 目标静默降级为无声。
（注：该模块目前尚无调用点，是预留的翻页音效开关。）

## 八、v1.73.0（build 121）· V2.0 模块四：导出沙盒合规

> 四项改动都只碰**导出层与打包脚本**，没动排版 / 分页 / 锚点。

### 1 · 导出目录记忆（沙盒安全落点）

记到 `Library::home()/last_export_dir.txt`——**应用数据目录**在 App Sandbox
下会被系统透明重定向到容器，**永远可写、无需任何授权**；反过来，真 `~`
下的自定义文件在沙盒里读不到，所以绝不能记到 `~/` 或 `~/.jiandu/`。

保存框起始目录优先级：**上次导出目录 → 桌面 → 交给系统记忆**。
目录已不在（外置盘拔了 / 用户删了 / 沙盒无权访问）→ 静默降级为「没记过」。

⚠️ 它只决定面板**从哪儿开**，不是访问授权。真正的写权限由 `NSSavePanel`
每次现场授予（entitlement `com.apple.security.files.user-selected.read-write`），
所以即便指到一个当前无权访问的目录也**不会崩**。

> 未做 security-scoped bookmark：bookmark 只省一次导航，而 `NSSavePanel`
> 每次都给授权，收益有限；且它要靠一组 NSURLBookmark 常量做 FFI，错了
> 会静默失效、本机又无从验证（GUI 被 TCC 拦）。需要「记住目录并持久访问」
> 时再单独做。

### 2 · 写盘归一：`exporter::save_bytes`

六条导出链路（本叶 PNG / 分享图 / MD / 朱批录 / 卡片 CSV ×2）统一出口：
补后缀 → 建父目录 → 写字节 → 记住目录。此前各自手写 `std::fs::write`，
**没人建父目录**——用户手敲一个还不存在的子目录就报
`No such file or directory`。

### 3 · 导出闸门 `export_busy`（事件监听修复）

除 PNG（靠 `png_export.is_some()`）外，MD / 卡片 ×2 / 批注四条**没有
重入保护**：`cx.spawn` 的 async 体是在**主线程**被 poll 的，保存面板浮起
前那几十毫秒里，第二次点击照样能进事件处理器 → 弹两个保存框、后一个把
前一个的状态冲掉。

- `Root` 新增 `export_busy` + `export_begin()` 入口占位；
- 五个 async 块统一改成「提示先算成值，最后只做一次 `update`」——
  **取消 / 成功 / 失败三态在同一处收口**，闸门复位与提示落地绑在一起，
  杜绝「某个分支忘了复位 → 导出永久锁死」；
- PNG 两段式在 `Shoot` 帧无条件先收 `png_export`（成败都收）。

> **PDF 导出**：v1.56.0 已移除，当前只有 PNG / 分享图 / MD / 批注 / CSV，
> 代码里残留的 `begin_pdf_export` 字样全是历史注释。

### 4 · `SANDBOX=1`：本地也能真跑沙盒

```bash
SANDBOX=1 ./scripts/make-mac-app.sh      # ad-hoc 签名也带 --entitlements
```

打出来的 `.app` 双击就直接跑在 App Sandbox 里——上传前可在本机把导入 /
导出 / 数据目录验一遍，不用等审核被打回。沙盒下数据目录会被重定向到
`~/Library/Containers/com.jiandu.app/Data/Library/Application Support/com.jiandu.app`，
**书架为空是正常的**（旧书在容器外，沙盒读不到），验收时重新导入一本即可。

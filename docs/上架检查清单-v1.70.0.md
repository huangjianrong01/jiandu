### 本轮修掉的三个真 bug

1. **数据目录分裂（会让老书集体变空白）**
   书架索引在 `~/Library/Application Support/com.jiandu.app`，章节库却硬拼 `~/.jiandu`。
   Mac App Store 强制沙盒后 `HOME` 被重定向到容器 → 两条路径必然分裂。
   本机实测：旧库 7 部 3385 章，新库 1 部 799 章。
2. **书架凭空少书**
   新索引 1 本（楚辞注），旧索引 8 本（资治通鉴 / 船山遗书 / 古文辞类纂 / 四库全书 /
   〔春秋〕左丘明 / 宋词三百首 / 历代名家词集精华录 / 中国古代名著全本译注）。
3. **取当前日期还要 fork 一个 `date` 子进程**（沙盒下外部进程随时可能被拦）。

### 本轮性能实测（《资治通鉴》799 章 / 12002 叶 / 308 万字）

| 指标 | 改前 | 改后 |
|---|---|---|
| 首帧建索引 | 345ms | **127ms** |
| 冷跳到末叶 | 244ms | **116ms**（且开卷后由渐进预热铺满，实际不再触发） |
| 连续翻页 | 130µs / 叶 | 130µs / 叶（本来就黄油，未变） |

三处根因：① `hydrate_chapter` 每章开一次数据库（open + 3 条 PRAGMA + ATTACH）；
② `scan_to` 前缀和 `for k in 0..end` 每推进一章把全表重加一遍（O(n²)，799 章白算 32 万次）；
③ 跳远时同步干完全部扫描。修法：线程本地读连接缓存 + 前缀和续加 + **空闲帧渐进铺索引**
（每帧 8 章 ≈ 1.1ms，60 FPS 无感，一两秒铺满，之后跳任何一章都是 O(log n) 查表）。

## 五、打包命令

### 通用包（arm64 + Intel x86_64，推荐，v1.71.0 起默认产出）

```bash
rustup target add x86_64-apple-darwin      # 只需做一次
ARCH=universal ./scripts/make-mac-app.sh   # → dist/笺读.app（105M）
cd dist && zip -rX -y ~/Desktop/笺读-1.71.0-universal.zip 笺读.app
```

> `lipo -archs dist/笺读.app/Contents/MacOS/jiandu` → **x86_64 arm64**，
> 一份包 Apple Silicon 与 Intel 都能装。本机架构那份复用 `target/release`
> （不重复全量编译），只有另一份进独立 target 子目录。

### 本机架构（只 Apple Silicon）

```bash
./scripts/make-mac-app.sh            # → dist/笺读.app
cd dist && zip -rX -y ~/Desktop/笺读-1.71.0.zip 笺读.app
```

> ⚠️ 必须用 `zip -rX -y`（`._` 边车文件会破坏签名），不要用 `ditto`。

### App Store 提审（你拿到证书后再跑）

```bash

APP_CERT="3rd Party Mac Developer Application: Your Name (TEAMID)" \
INSTALLER_CERT="3rd Party Mac Developer Installer: Your Name (TEAMID)" \
PROVISIONING_PROFILE=scripts/embedded.provisionprofile \

```

产出 `dist/笺读-1.70.0-118.pkg`，用 **Transporter**（或 Xcode Organizer）上传到 App Store Connect。

> MAS 提审**不需要自己公证**（Apple 统一处理）。

## 七、v1.71.0（build 119）：第 15 / 16 / 18 条已解决

### 15 + 16 · 剪贴板原生化（osascript / pbpaste / pbcopy 全部下岗）

新增 `src/clipboard.rs` 作为**剪贴板唯一入口**，统一走 GPUI 平台层的
`App::write_to_clipboard / read_from_clipboard`——macOS 实现就是
`NSPasteboard.generalPasteboard()`：**零子进程、零新依赖、零权限弹窗**，
不需要 `com.apple.security.automation.apple-events`。

| 原实现 | 位置 | 新实现 |
|---|---|---|
| `osascript` 写 `«class PNGf»`（还要先落临时 PNG） | `reader.rs::copy_share_png` | `clipboard::write_png` 直写 `public.png` UTI，**不落盘** |
| `pbcopy` 灌 stdin | `reader.rs::copy_page_text` | `clipboard::write_text(cx, …)` |
| `pbpaste` 子进程 | `app.rs::note_paste` | `clipboard::paste_text(cx)`（换行压成空格，口径不变） |
| `pbpaste` 子进程 | `shelf.rs` 重命名框 / 书架搜索框 ⌘V | 同上 |

`note_paste` 签名改为 `note_paste(&mut self, text: &str)`——剪贴板由调用方
读，草稿模型保持纯粹。新增 2 条单测（换行压平 / 一字不落），全量
**548 passed / 0 failed**。

### 「导出当前页图片」新链路（用户点名要打通的三段）

1. **底层 `render_leaf_png`（reader.rs）** —— 离屏重绘，不读屏幕：
   * 正文取自**当前叶的排版结果**（`page_at` → 只要 `GlyphKind::Char`，
     繁简形态与屏幕一致，朱批逐字带过来）；
   * 走 `share_layout::layout` → `share_paint::render_png`（CoreGraphics
     位图 + CoreText 逐字落笔），与分享卡同一套已验证的光栅器；
   * 画面只留 **宣纸 + 天头地脚 + 版框界行 + 正文 + 朱印**：落款 / 日期 /
     批注列 `show_*` 全 false——**顶栏、页码、浮层都进不了图**；
   * 纸色 / 栏色**跟阅读界面当前主题走**（纸色亮度分宣纸 / 暗金，丝栏偏朱
     取朱丝栏、否则乌丝栏），不是分享抽屉那套偏好；
   * 分辨率**与窗口无关**：长边恒 **2160（2× 高清）**，短边按纸面真实比例
     （`leaf_png_size`），探针取不到尺寸时回退 1080×1920 基准。
   ⚠️ **只读排版结果，一行没碰排版引擎**（分页 / 网格 / 锚点全未改）。
2. **原生保存框（rfd）** —— 默认名 **`笺读_<书名>_第N叶.png`**（可改）；
   对话框标题「印制本叶（高清 PNG）」；**取消 = 正常结果**（提示「已取消保存」，
   不 panic、不报错红）；落盘不再「先写临时文件再拷一份」，直接写字节。
3. **UI 菜单绑定** —— 顶栏「导出」→「导出当前页图片」→ `export_page_png`
   （保持 `on_mouse_down`：阅读根 div 上挂着「点纸面收菜单」的 mousedown，
   改 `on_click` 会让菜单在抬起前被卸载、click 永不触发，详见代码注释）。
   成功后弹极简 Toast：**「本叶已印制」**（副行只带文件名，完整路径进 `notice`）。

**Toast 的三种收起方式**：点右侧「关」/ 按 **Esc** / 点纸面任一处。
单字按钮用 CJK「关」（U+2715 那类拉丁区符号在 GPUI 里是零宽，画不出来）。
帮助面板「导出」组新增四行说明（清晰度口径 / 文件名 / 提示如何收起），
「Esc」行的说明也补上了「收起导出提示条」。

### 17 · `afplay` → 原生 `NSSound`

`sound::page_turn` 不再 fork 子进程：FFI 直调 `objc_getClass` /
`sel_registerName` / `objc_msgSend`（都在 libobjc 里，**不加新依赖**），
`[[NSSound alloc] initWithContentsOfFile:byReference:]` 建一台对象缓存复用，
`play` 本身异步、主线程直调不阻塞。非 macOS 目标静默降级为无声。
（注：该模块目前尚无调用点，是预留的翻页音效开关。）

## 八、v1.73.0（build 121）· V2.0 模块四：导出沙盒合规

> 四项改动都只碰**导出层与打包脚本**，没动排版 / 分页 / 锚点。

### 1 · 导出目录记忆（沙盒安全落点）

记到 `Library::home()/last_export_dir.txt`——**应用数据目录**在 App Sandbox
下会被系统透明重定向到容器，**永远可写、无需任何授权**；反过来，真 `~`
下的自定义文件在沙盒里读不到，所以绝不能记到 `~/` 或 `~/.jiandu/`。

保存框起始目录优先级：**上次导出目录 → 桌面 → 交给系统记忆**。
目录已不在（外置盘拔了 / 用户删了 / 沙盒无权访问）→ 静默降级为「没记过」。

⚠️ 它只决定面板**从哪儿开**，不是访问授权。真正的写权限由 `NSSavePanel`
每次现场授予（entitlement `com.apple.security.files.user-selected.read-write`），
所以即便指到一个当前无权访问的目录也**不会崩**。

> 未做 security-scoped bookmark：bookmark 只省一次导航，而 `NSSavePanel`
> 每次都给授权，收益有限；且它要靠一组 NSURLBookmark 常量做 FFI，错了
> 会静默失效、本机又无从验证（GUI 被 TCC 拦）。需要「记住目录并持久访问」
> 时再单独做。

### 2 · 写盘归一：`exporter::save_bytes`

六条导出链路（本叶 PNG / 分享图 / MD / 朱批录 / 卡片 CSV ×2）统一出口：
补后缀 → 建父目录 → 写字节 → 记住目录。此前各自手写 `std::fs::write`，
**没人建父目录**——用户手敲一个还不存在的子目录就报
`No such file or directory`。

### 3 · 导出闸门 `export_busy`（事件监听修复）

除 PNG（靠 `png_export.is_some()`）外，MD / 卡片 ×2 / 批注四条**没有
重入保护**：`cx.spawn` 的 async 体是在**主线程**被 poll 的，保存面板浮起
前那几十毫秒里，第二次点击照样能进事件处理器 → 弹两个保存框、后一个把
前一个的状态冲掉。

- `Root` 新增 `export_busy` + `export_begin()` 入口占位；
- 五个 async 块统一改成「提示先算成值，最后只做一次 `update`」——
  **取消 / 成功 / 失败三态在同一处收口**，闸门复位与提示落地绑在一起，
  杜绝「某个分支忘了复位 → 导出永久锁死」；
- PNG 两段式在 `Shoot` 帧无条件先收 `png_export`（成败都收）。

> **PDF 导出**：v1.56.0 已移除，当前只有 PNG / 分享图 / MD / 批注 / CSV，
> 代码里残留的 `begin_pdf_export` 字样全是历史注释。

### 4 · `SANDBOX=1`：本地也能真跑沙盒

```bash
SANDBOX=1 ./scripts/make-mac-app.sh      # ad-hoc 签名也带 --entitlements
```

打出来的 `.app` 双击就直接跑在 App Sandbox 里——上传前可在本机把导入 /
导出 / 数据目录验一遍，不用等审核被打回。沙盒下数据目录会被重定向到
`~/Library/Containers/com.jiandu.app/Data/Library/Application Support/com.jiandu.app`，
**书架为空是正常的**（旧书在容器外，沙盒读不到），验收时重新导入一本即可。

## 十、v1.75.0（build 123）· 佛经「品」分章 + FTS5 全文检索

### 一、《金刚经》这类按「品」分节的书：一品为一章

网上的佛经 txt 常见两种形态，此前**都不被认作章节**：

```text
金刚经第一品 法会因由分          ← 书名前缀 + 品题（判据要求行首是「第」，前缀一挡全不认）
…是名一合相。第二十九品 威仪寂静分须菩提。…   ← 品题与正文黏成一坨
```

四步修法（全部落在**清洗层**，排版引擎一行没碰）：

1. `cleaner::HEAD_UNITS` 补 **品 / 颂 / 偈 / 门 / 赞**。
   ⚠️ 没放「分」「经」「论」「传」——正文里太常见，放进来必然误杀。
2. `is_chapter_head` 允许 ≤8 个汉字的短前缀，并支持**后置序数**
   （「法会因由分第一」）。顺手修了 `cs[i]` 的**越界 panic**：「第二十九」
   「第108」这类孤序数会让 `i` 走到末尾，此前直接把整次导入炸掉。
3. `cleaner::split_inline_heads`：把黏成一坨的品题断成三行（前刀 + 品名
   尾字后刀），判据三条全中才切（有品名尾字 / 后面还粘着 ≥20 字 / 前一格
   不是收尾引号），**只插换行、一个字不删**。接进 TXT 链与
   `cleanup_ancient_text`（六格式共用）。
4. `pipeline::resplit_by_heads`：清洗后统一再扫一遍行首标题开章——EPUB /
   HTML 只认 `<h1>` 结构标签，品题在它们眼里只是普通段落，断行之后仍赖在
   上一品的章里。六格式口径归一。

**尊重原文**：品题长什么样，章标题就是什么样（不自作主张剥书名前缀）；
扉页那行书名一个字不删，挪去当章标题，由既有的「首章无正文 → 提为书名」
约定收作书名。

真实文件验证：《金刚经》txt → **32 品 = 32 章**
（第一品 法会因由分 … 第三十二品 应化非真分）。

### 二、FTS5 全文检索（V2.0 模块一）

现状是 `Book::search` 全书**逐字线性扫描**，799 章的书每搜一次要把每一段
摊开比对一遍。换成 FTS5 倒排索引 + `trigram` 分词：

- **分词器必须是 trigram**：默认的 `unicode61` 按空格切词，整段中文会被
  当成**一个 token**，搜「长安」等于全表扫，索引白建。
- **索引按需建**：trigram 索引比正文还大，书架里躺着二十本书，没搜过的
  一本都不该占空间——只有第一次搜某本书才为它建。
- **<3 字的查询仍走内存扫描**：SQLite 文档明说 trigram 用不上短查询的索引。
- **不用 external content**：章节表没有稳定的 INTEGER PRIMARY KEY（主键是
  复合的 `(store_id, idx)`），靠隐式 rowid 做 `content_rowid`，一旦删章 /
  重灌就对不上，错起来是**静默返回空结果**——比多占一倍磁盘危险得多。
- 查询串一律包成 phrase，避开 FTS5 的 `AND` / `OR` / `*` 语法。
- 建索引 + 查询整段丢给 `background_executor`，主线程只管出结果，不卡翻页。
- 删书时同步清索引。

### 验证

`cargo test --workspace --release` = **566 passed / 0 failed**
（561 基线 + 5 条 FTS：候选章定位 / 按书隔离 / 未索引返回空而非报错 /
语法字符转义 / 删书清索引）。

## 十一、v1.76.0（build 124）· V2.0 模块二：问小笺（AI 伴读）

### 一、它是什么

框选一句 → 浮签「问笺」→ 右侧滑出小笺，把**这句原文 + 前后文 + 书名章名**
发给你自己选的服务商，流式回话。工具条上原来的「人名 / 地名 / 书名」三枚
钮同步撤掉——有问笺之后，专名标注是多余的中间态。

### 二、架构要点

- **核心逻辑全在 `core/src/ai.rs`，零网络零 GPUI**，可单测：8 家 OpenAI
  兼容服务商预设（深度求索 / 月之暗面 / 通义 / 智谱 / OpenAI / 硅基流动 /
  本机 Ollama / 自定义），提示词组装（出处 → 前文 → 原文 → 后文 →
  **问题压在最末**，短问题贴着原文更容易被模型抓住）。
- **SSE 解析按字节攒缓冲**，见 `\n` 才成行。中文一个字三个字节，TCP 常把
  它切在中间——按行读会吐出半个汉字的乱码，这条有单测钉死。
- **面板是独立 Entity**（`src/ai.rs` 的 `AiPanel`）。流式输出每秒 notify
  几十次，状态若住在 `Root` 里，每一次都会带着整棵阅读树重排一遍——书会
  肉眼可见地抖。独立 Entity 只重绘这一条侧栏。
- **输入框能接中文 IME**：把 `ime::InputField` 从写死的 `Entity<Root>` 放宽
  成泛型，问笺的地址 / 模型 / 密钥 / 提问四框复用同一套。
- **网络栈不引新依赖**：hyper / hyper-rustls / tokio 在 Cargo.lock 里本来
  就有（gpui 依赖树自带），锁文件只多几行引用，**离线可编**。
  `https_or_http()` 让本机 Ollama 的 `http://` 也能走。工作线程
  `catch_unwind` 兜底，网络出错降级成面板里一句人话，不崩。

### 三、⚠️ 上架必读：隐私声明（这是唯一会卡审核的点）

问笺会把**用户选中的原文**（以及前后各一小段上下文）发往用户在设置里
**自己填的地址**。App Store 审核会盯这条，提交前必须做三件事：

1. **`jiandu.entitlements` 已补 `com.apple.security.network.client`**
   （v1.76.0 已加）。沙盒下不给出站权限，连不上就是一句「网络未通」。
2. **App Store Connect → App Privacy 要如实勾选**：
   - *Data Not Linked to You*：若只发原文、不采集用户标识；
   - 若服务商侧能关联到人，则归 *Data Linked to You → User Content*。
   - 目的填 **App Functionality**。
3. **App 内要有可见提示**——帮助面板「问小笺」一节已写明「问一句就把这句
   原文发给你选的服务商」，首启设置页也提醒「密钥只存在本机」。审核员会在
   App 里找这句话，找不到容易被打回。

密钥单独落 `~/Library/Application Support/com.jiandu.app/ai.json`，权限
**0600**；界面回显一律走 `key_mask`（`sk-···mnop`），日志不吐明文。

## 十二、v1.77.0（build 125）· 批量导入 EPUB（异步队列 / 进度 / 延迟建索引 / 容灾 / 可取消）

### 一、旧状：多选等于没选

`import_dialog` 用的是 `pick_files()`（可多选），但 `add_import` 一次只收一本，
第二本起全被「还有一部书正在刻印，请稍候」**静默挡掉**。用户选了十本，书架上
只出现一本，还以为是自己点错了。

### 二、五条硬性要求的落法

| 要求 | 落法 |
|---|---|
| ① 异步串行 | 整队丢进 `std::thread::spawn`（与单本 `ImportJob` 同一条老路），主线程一帧不等 |
| ② 进度反馈 | 浮层「正在导入 3/10：书名」+ 总进度条 + 本本进度条 + 已上架/跳过计数 |
| ③ 延迟建索引 | 点检只读 OPF（元数据 + 目录），正文后台刻；FTS5 索引另起线程一本一本慢慢补 |
| ④ 防崩溃容灾 | 每本各自 `catch_unwind`，坏文件跳过并写 `import-log.txt`，队列继续 |
| ⑤ 可取消 | 浮层「取消」/ Esc → 置标记，手上这本刻完即停，半成品 `store_id` 全部删库 |

**为什么是串行（并发 1）而不是 2**：`chapters.db` 是同一个 SQLite 文件，两条
导入线程同时写会撞 `busy_timeout`（5s），轻则等、重则报 `database is locked`。
批量导入的瓶颈是「解析 + 清洗」的 CPU，串行已经能吃满一个核；再并行只是拿
稳定性换一点点速度，不划算。

### 三、两趟结构：先点检，后刻印

```text
第一趟 点检(毫秒级)  解 container.xml → OPF → dc:title / dc:creator → ncx / nav 目录
                     ↓ 立刻发布
       书架出现「待刻书衣」（褪色布面 + 「待刻 · N 章」，不可点开）
第二趟 刻印(秒级/本)  import_streaming 逐章落 chapters.db → 刻完一本上架一本
                     ↑ 每本独立 catch_unwind
```

- **为什么书衣不可点开**：半成的书点开是一片白纸，比「还没出现」更像崩了。
- **点检的另一桩好处**：坏文件在开刻**之前**就被剔掉（不占队列名额），
  而不是刻到一半才崩。
- 真实样本（9 个文件 / 68MB，含 1 个假 EPUB、1 个 PDF）：点检 **0–14ms/本**
  （32MB 的《明实录》14ms），假 EPUB 被认成「不是合法的 zip 容器」并跳过，
  PDF 连队列都进不去。

### 四、延迟建索引：不再是「导入时顺手建」

FTS5 的 `trigram` 索引比正文还大。批量导入二十本时若每本都当场建，首屏要卡
好几秒。现在：

- 导入只管落正文，`store_id` 推进 `fts_queue`；
- 一条**后台线程**一本一本地 `search::ensure`，跑完一批自动接下一批；
- 用户若在补完之前就搜这本书，`run_search` 里的 `ensure` 会当场补上——
  慢的是「第一次搜这本」，不是「导入」。

### 五、取消与半成品清理

取消只置标记（`import_streaming` 内部没有可中断点，硬杀会留半截事务）。
语义定死三条：

1. 取消**之前**已上架的书，一本都不删（用户已经看见了）；
2. 取消时正在刻的那本，刻完也**不上架**，其 `store_id` 进 `orphans`；
3. `orphans` 里的 `store_id` 由主线程 `store::delete_book` 删净
   （章 + 书 + FTS 索引三样一起），并跳过已上架清单里的那些。

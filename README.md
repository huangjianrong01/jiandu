# 笺读 · JianDu

> 一个用 **Rust + GPUI** 写的原生中文阅读器：**书架 → 封面 → 阅读** 三段式，古文竖笺从右到左列排（**列数随内容自适应 8/10/12/14**），支持单双面对开、繁体与通假标注、双行夹注。

灵感来自《我现在是如何用AI读〈经济学人〉的？》里的一句话——**为阅读这件事创造环境**。笺读把「为自己搭一个阅读器」做成真正的原生桌面应用：你负责读、选、学，排版与记忆交给程序。

## 🚀 快速开始

### 1. 环境

- Rust（stable，建议 ≥ 1.75）
- macOS 或 Linux（GPUI 目前主要面向这两个平台）
- 系统字体：建议安装 **思源宋体** 与 **思源黑体**；未安装时沿回退链使用系统宋体 / 黑体。

### 2. 运行

```bash
cargo run --release
```

> GPUI 固定使用 crates.io 稳定版 `0.2.2`（不跟随 Zed `main` 分支，保证可复现构建）。如需换版本，改 `Cargo.toml` 里的 `gpui` 版本号即可。

### 3. 数据目录

```
~/.jiandu/
├── library.json      # 书架索引 + 每本书的阅读档案
└── books/            # 导入的书籍副本
```

可用环境变量 `JIANDU_HOME` 改到别处。首次启动会自动把《道德经》样张写进书架，书架不会空着。

## 📲 安装到 Mac / iPhone

### macOS：打包成「笺读.app」

```bash
./scripts/make-mac-app.sh                 # 编译 release 并打包
# 已有 release 二进制、想跳过编译时：
SKIP_BUILD=1 CARGO_TARGET_DIR=~/jiandu-target ./scripts/make-mac-app.sh
```

产出 `dist/笺读.app`（约 7 MB，内置图标 + ad-hoc 签名），就是一个可直接双击的原生 App：

1. 双击打开；首次若被 Gatekeeper 拦下，右键图标 →「打开」→ 再点一次「打开」。
2. 或直接拖进「应用程序」文件夹，之后从启动台 / Dock 打开。
3. 卸载：把 App 拖进废纸篓即可；用户数据在 `~/.jiandu/`，可留可删。

### iPhone：Xcode 工程

工程在 `ios/JianDu/JianDu.xcodeproj`。

- **模拟器**：用 Xcode 打开，选一台 iPhone 模拟器，⌘R 运行。
- **真机**：`Signing & Capabilities` 里选自己的 Apple ID（免费个人团队即可），连上 iPhone 后选设备运行。免费签名 7 天有效，到期重装；要长期分发 / 上架需付费开发者账号。
- **命令行装进已启动的模拟器**：

```bash
xcodebuild -project ios/JianDu/JianDu.xcodeproj -scheme JianDu \
  -configuration Debug -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
xcrun simctl install booted ~/Library/Developer/Xcode/DerivedData/JianDu-*/Build/Products/Debug-iphonesimulator/JianDu.app
xcrun simctl launch booted com.jiandu.ios
```

iOS 端与 Mac 端共用同一套 `Book` JSON：书架封面墙、封面页、古文竖笺 / 横笺、繁体 / 通假 / 注释、目录、翻页手势都在；导入支持「文件」App 里的 `.json / .md / .txt / .epub`。

## 📦 支持的导入格式

### txt

按「第 X 章 / 回 / 节 / 卷」自动分章，空行分段。支持行内注释标记（见下）。

### md（Markdown）

首个 `#` 一级标题作书名，`#`/`##` 标题分章，剥离 `**粗体**`、`[链接](url)`、`` `代码` `` 后按空行分段。

### json

完整 Book 结构（推荐，支持封面、通假表、逐段注释）：

```json
{
  "title": "道德经",
  "author": "老子",
  "cover": { "title": "道德经", "subtitle": "八十一章 · 五千言", "seal": "笺读" },
  "tongjia": { "见": "现", "知": "智" },
  "chapters": [
    {
      "title": "第一章",
      "paragraphs": [
        {
          "text": "道可道，非常道。名可名，非常名。",
          "notes": [
            { "at": 0, "kind": "note", "text": "道：宇宙万物的本原。" },
            { "at": 12, "kind": "tongjia", "text": "见，通「现」" }
          ]
        }
      ]
    }
  ]
}
```

`paragraphs` 里的元素也**可以直接是字符串**，无需注释时更省事：

```json
{ "title": "某章", "paragraphs": ["第一段。", "第二段。"] }
```

### epub（原生支持，含目录）

直接读 `.epub`，不需要先转换，流程是：

1. `META-INF/container.xml` → 找到 OPF；
2. OPF 的 `metadata` 取书名、作者；
3. 按 `spine` 顺序抽取各 XHTML 正文（去标签、去脚本样式）；
4. **解析目录**：优先 EPUB3 的 `nav.xhtml`（`epub:type="toc"`），
   回退 EPUB2 的 `toc.ncx`，按嵌套层级还原多级目录；
5. 目录条目的 href（含 `#锚点`）映射到章节序号，用于跳转。

于是导入后：工具栏的「☰ 目录」打开目录侧栏，点任意条目直接跳到该章首面，
当前所在章会高亮。

## 🧭 目录与格式转换

### 目录

- 工具栏「☰ 目录」开合目录侧栏；
- 条目按 `level` 缩进，多级目录（卷 → 章）能看出来；
- 点击条目跳到该章**第一面**，当前章高亮并带 ▸ 标记；
- epub 自带目录优先；txt / md / json 没有目录时，按章节标题自动生成一份。

### 把 epub 转成 json / txt / md

不必开窗口，命令行直接转换：

```bash
# epub -> json（保留封面、目录、注释，回笺读读最完整）
cargo run --release -- --convert 书.epub --out 书.json

# epub -> 带目录的 txt（输出到同目录同名 .txt）
cargo run --release -- --convert 书.epub --format txt

# 也可以直接 cargo run -- -c 书.epub -o 输出.md
```

三种格式的差别：

| 格式 | 保留目录 | 保留注释 | 适用 |
| --- | --- | --- | --- |
| `json` | ✅ 含层级 | ✅ 含通假 | 回笺读，或交给别的程序处理 |
| `txt` | ✅ 顶部目录清单 | ✅ 段后 `〔注〕` | 想用任何编辑器改稿、投喂给 LLM |
| `md` | ✅ 列表形式 | ⚠️ 仅正文 | 写笔记、发博客、再导入 |

`txt` 的输出长这样：

```text
《道德经》
作者：老子
全书 3 章 · 约 5200 字

——— 目录 ———

上篇 道经
    第一章 道可道
下篇 德经

——— 正文 ———

上篇 道经

道可道，非常道。……
〔注〕道：宇宙万物的本原。
```

## ✍️ 行内注释标记（txt / md 手写更省事）

在正文里直接写，导入时自动解析并转为注释：

| 标记 | 含义 | 示例 |
| --- | --- | --- |
| `字〖注文〗` | 普通注（圈号脚注），锚定**前一个字** | `道〖宇宙万物的本原〗可道` |
| `字≪本字≫` | 通假标（靛蓝小字） | `不见≪现≫可欲` |

标记本身会从正文中剥离，阅读时只显示干净原文 + 朱红圈号或靛蓝标注。

## 📐 版式参数

**唯一网格入口是 `grid::calculate_grid(GridInput)`**（`src/grid.rs`）。模式只在那儿分派一次，
之后三种模式共用同一套算式：

```text
col_w = 可用宽 / 列数
fs    = clamp(0.75 × col_w × zoom, GRID_FS_MIN, GRID_FS_MAX)
row_h = GRID_ROW_RATIO × col_w × lineScale        // 1.0 × 列宽 × 行高缩放
rows  = floor(可用高 / row_h)
```

```rust
pub const GRID_COLUMN_CHOICES: [usize; 4] = [8, 10, 12, 14]; // 可切列数
pub const GRID_FS_RATIO: f32 = 0.75;   // 字号 = 0.75 × 列宽
pub const GRID_ROW_RATIO: f32 = 1.0;   // 行高 = 1.0 × 列宽（v1.28.0 由 1.1 收紧）
pub const GRID_FS_MIN: f32 = 12.0;     // 字号下限：窄屏跌破则反推列宽，宁可横向滚动
pub const GRID_FS_MAX: f32 = 32.0;     // 字号上限（v1.28.0 由 220 收来）：避免「大字本」
```

两个方向的兜底：

- **触下限**（窄屏 14 列）：字号优先，反推列宽放大，宁可溢出滚动。
- **触上限**（大屏对开）：列宽随之回缩到「字刚好贴格」，保住字与格 0.75 的比例——只压字号
  不回缩列宽的话，字会缩在格心、纸面反而更空。但**最多只缩到原列宽的 70%**，再窄就是一条纸带。
- 整页模式（`Full`）与专注模式传 `f32::INFINITY` 豁免上限：前者要等比缩放，后者要满屏大字。

### 列数随内容自适应（v1.29.0）

默认不再一刀切排 12 列，而是**按这本书的篇幅选档**——短章语录字大行疏、长篇章回字小行密，
这正是刻本的做法：

```rust
pub const AUTO_SHORT_CHARS: usize = 150;    // 平均一章多少字
pub const AUTO_MID_CHARS: usize = 500;
pub const AUTO_LONG_CHARS: usize = 1200;

pub fn content_columns(avg: usize) -> usize {
    if avg < AUTO_SHORT_CHARS { 8 }         // 语录 / 短札（《道德经》《三字经》）
    else if avg < AUTO_MID_CHARS { 10 }     // 词集 / 短篇集
    else if avg < AUTO_LONG_CHARS { 12 }    // 常篇
    else { 14 }                             // 长篇章回（《资治通鉴》《史记》）
}
```

两条规则，主次分明：

1. **内容定档**（`content_columns`）：篇幅是主因，屏幕管不着。
2. **屏幕兜底**：只有当该档字号跌破 `GRID_FS_MIN`（12px）时，才逐级往少列退
   （列少 → 列宽大 → 字大）。

> **字号触顶不是「该加列」的信号。** 早先的版本拿「字号接近某个目标值」打分，结果在宽屏上
> 8/10/12 列的字号全被 `GRID_FS_MAX = 32` 压成同一个数，判据失去区分度，任何书都只能选最密档
> ——自适应名存实亡。触顶时 `compute_grid` 会让列宽回缩、纸面变窄居中，那正是「疏朗而不空旷」，
> 是短章该有的样子。

面板「版式 → 列数」末尾有「自动」一项（默认开）。点具体某一档即锁定（`columns_auto = false`），
点回「自动」再放开。拉窗口跨档时用 `pending_anchor` 保住阅读位置，不会跳页。

> 早期版本用固定常量（`ANCIENT_ROWS = 8` / `ANCIENT_PER_ROW = 11` / `MODERN_LINES = 12`）
> 定分页容量，与「现代横笺」一起已移除；现在行数由可用高反算，横排渲染不再保留。

## ⚠️ 已知限制

- GPUI 仍在活跃开发中，API 可能随版本变动；若编译报错，请按 Zed 官方示例调整调用。
- 竖排采用逐字布局（每字一个元素），超大文本时性能会下降，后续可改为一次性 shaping 绘制。
- 简繁与通假表目前覆盖常用及典籍用字（`src/trad.rs`、`types.rs` 的 `book.tongjia`），可按需扩充。
- 阅读档案记录页码、排版模式与单双面选择；字体与字号暂不随书保存（全局偏好）。
- 笔记输入为自绘行内编辑（GPUI 0.2.2 无文本输入元素 / IME 通路）：可键入英文数字、⌘V 粘贴中文，中文需借助剪贴板。
- 朱雀仿宋 / 京华老宋 / 汇文明朝 / 汇文正楷 / 寒蝉活仿楷 / 寒蝉锦书宋 六款为开源字库，随包未内置（体积过大）：把 `.ttf/.otf` 放进 `resources/fonts/` 再打包（脚本会自动带上），或直接装进系统即可选中；未安装时自动回退到最接近的系统字体。
- 保存 / 分享图片走 `screencapture` 按卡片矩形裁切：需要屏幕录制权限，且若桌面上有别的窗口压在应用上方，会被一起截进去（把它移开或先切到笺读再保存即可）。
